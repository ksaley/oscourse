ДИЗАЙН-ДОКУМЕНТ: РЕАЛИЗАЦИЯ EEVDF ПЛАНИРОВЩИКА В JOS
=====================================================

1. ОБЗОР
--------

В рамках индивидуального задания реализован альтернативный планировщик
на основе алгоритма EEVDF (Earliest Eligible Virtual Deadline First)
для операционной системы JOS. Планировщик обеспечивает поддержку
latency и честности планирования, а также включает блокирующие
примитивы синхронизации.

2. АЛГОРИТМ EEVDF
-----------------

2.1 Основные концепции

EEVDF (Earliest Eligible Virtual Deadline First) - это алгоритм
планирования с пропорциональным распределением ресурсов, который
использует следующие понятия:

- Виртуальное время (virtual runtime): накопленное виртуальное время
  выполнения процесса, нормализованное по весу процесса
- Виртуальный дедлайн (virtual deadline): момент виртуального времени,
  к которому процесс должен завершить свой квант
- Вес процесса (weight): определяет долю процессорного времени,
  выделяемую процессу

2.2 Формулы

- Виртуальное время обновляется: vruntime += (runtime * total_weight) / weight
- Виртуальный дедлайн: vdeadline = vruntime + (slice_size / weight)
- Процесс считается eligible, если: vruntime <= min_vruntime + latency

2.3 Реализация

Планировщик поддерживает:
- Очередь процессов, отсортированную по виртуальному дедлайну
- Минимальное виртуальное время для обеспечения честности
- Поддержку latency через параметр eligibility window
- Автоматическое пробуждение спящих процессов

3. СТРУКТУРЫ ДАННЫХ
------------------

3.1 Расширение struct Env

Добавлены следующие поля в структуру Env:
- env_weight: вес процесса (по умолчанию 1024)
- env_vruntime: виртуальное время выполнения
- env_vdeadline: виртуальный дедлайн
- env_slice_start: момент начала текущего кванта (TSC)
- env_sleep_until: момент пробуждения для спящих процессов
- env_sched_link: указатель для связи в очереди планировщика

3.2 Состояние планировщика

- sched_runnable_head: голова очереди готовых процессов
- sched_min_vruntime: минимальное виртуальное время
- sched_total_weight: суммарный вес всех процессов

4. СИСТЕМНЫЕ ВЫЗОВЫ
------------------

4.1 sys_sched_setparam

Назначение: установка параметров планирования процесса

Параметры:
- weight: вес процесса (1-1000000)

Возвращает: 0 при успехе, -E_INVAL при ошибке

4.2 sys_sleep

Назначение: блокировка процесса на указанное время

Параметры:
- usec: время ожидания в микросекундах

Возвращает: 0

4.3 sys_mutex_init, sys_mutex_lock, sys_mutex_unlock, sys_mutex_trylock

Назначение: операции с мьютексами

Параметры:
- m: указатель на структуру Mutex

4.4 sys_condvar_init, sys_condvar_wait, sys_condvar_signal, sys_condvar_broadcast

Назначение: операции с условными переменными

Параметры:
- cv: указатель на структуру CondVar
- m: указатель на связанный мьютекс (для init)

5. БЛОКИРУЮЩИЕ ПРИМИТИВЫ СИНХРОНИЗАЦИИ
-------------------------------------

5.1 Mutex

Реализован блокирующий мьютекс с очередью ожидания:
- mutex_lock: блокирует процесс, если мьютекс занят
- mutex_unlock: освобождает мьютекс и пробуждает первый ожидающий процесс
- mutex_trylock: неблокирующая попытка захвата

5.2 Condition Variable

Реализованы условные переменные с поддержкой:
- condvar_wait: ожидание условия (автоматически освобождает мьютекс)
- condvar_signal: пробуждение одного ожидающего процесса
- condvar_broadcast: пробуждение всех ожидающих процессов

6. ТЕСТЫ
--------

6.1 test_sched.c - Тест честности планирования

Проверяет, что процессы с разными весами получают пропорциональное
количество процессорного времени. Запускается с несколькими процессами,
каждый устанавливает свой вес и выполняет цикл с yield.

Ожидаемый результат: процессы с большим весом получают больше
процессорного времени.

6.2 test_sleep.c - Тест системного вызова sleep

Проверяет корректность работы sys_sleep:
- Процесс блокируется на указанное время
- Процесс пробуждается по истечении времени

Ожидаемый результат: процесс просыпается через указанное время.

6.3 test_mutex.c - Тест мьютексов

Проверяет корректность работы мьютексов:
- Несколько процессов пытаются инкрементировать общий счетчик
- Мьютекс защищает критическую секцию

Ожидаемый результат: счетчик увеличивается корректно, без гонок.

6.4 test_condvar.c - Тест условных переменных

Проверяет корректность работы условных переменных:
- Процесс ожидает условия
- Другой процесс сигнализирует о выполнении условия

Ожидаемый результат: ожидающий процесс пробуждается после сигнала.

7. АРХИТЕКТУРНЫЕ РЕШЕНИЯ
-----------------------

7.1 Интеграция с существующим кодом

- Планировщик интегрирован в существующую систему через sched_yield()
- Новые процессы автоматически добавляются в очередь при создании
- Таймерные прерывания вызывают sched_yield() для перепланирования

7.2 Управление временем

- Используется TSC (Time Stamp Counter) для измерения времени выполнения
- Частота CPU определяется через timer_for_schedule->get_cpu_freq()
- Виртуальное время нормализуется относительно реального времени

7.3 Обработка спящих процессов

- Спящие процессы имеют статус ENV_NOT_RUNNABLE
- При каждом вызове sched_yield() проверяются спящие процессы
- Проснувшиеся процессы автоматически добавляются в очередь

8. ОГРАНИЧЕНИЯ И БУДУЩИЕ УЛУЧШЕНИЯ
----------------------------------

8.1 Текущие ограничения

- Планировщик работает только в однопроцессорной системе
- Мьютексы и condvar используют env_sched_link для очередей ожидания
  (в реальной системе нужна отдельная структура)
- Нет поддержки приоритетов процессов

8.2 Возможные улучшения

- Поддержка многопроцессорных систем
- Динамическая настройка latency window
- Поддержка групп процессов (cgroups)
- Статистика планирования

9. КОМПИЛЯЦИЯ И ЗАПУСК
---------------------

Для компиляции:
  make

Для запуска тестов необходимо создать соответствующие процессы
в init.c и добавить их в список ENV_CREATE.

10. ПРОВЕРКА КОРРЕКТНОСТИ
-------------------------

Код проверен на:
- Отсутствие утечек памяти
- Корректность работы с ASAN/UBSAN
- Правильность синхронизации процессов
- Честность распределения процессорного времени

Все системные вызовы возвращают корректные коды ошибок и
обрабатывают граничные случаи.
